## 二、開發優先級原則

本文檔按 **兩個維度** 對功能進行排序：

| 優先級 | 維度 | 說明 |
|--------|------|------|
| **P0（最高）** | 核心差異化功能 + 易實現 + 用戶能感知 | MVP 必須包含，且 AI 編程工具能高效生成 |
| **P1（高）** | 核心功能 + 中等難度 | MVP 後第一輪迭代加入 |
| **P2（中）** | 增強功能 + 需要較多人工調試 | 產品化階段加入 |
| **P3（低）** | 高級功能 + 複雜度高 | 驗證成功後規劃 |

**核心開發理念（v4 強化）**：

> 1. 優先交付用戶**能感知到價值**的功能，而非完美的功能
> 2. 🆕 **誤報率比檢出率更重要**——寧可漏報，不可錯殺
> 3. 🆕 **殺手場景 > 功能數量**——一個讓用戶「裝上就不想卸」的場景，比十個平庸功能更有價值

## 十二、我的關鍵意見（v4 補充）

### 1. 為什麼要做「安裝前掃描」這個殺手功能？

> 競品分析中提到「NVIDIA SkillSpector 已驗證 Skill 三層掃描可行」。但 SkillSpector 是**企業級工具**，要安裝、要配置、要登錄。
>
> 我們的目標用戶是**個人開發者**，他們的特點是：
> - 看到一個想用的 skill
> - 猶豫 30 秒（這個安全嗎？）
> - **要裝的話馬上就要裝**，不會先去運行 CLI 工具
>
> 「對話式 `/safety-check`」解決了「要記得運行」的問題，但沒解決「要**主動**運行」的問題。
>
> **「安裝前掃描」直接嵌入用戶的決策路徑**——這就是殺手場景。

### 2. 為什麼誤報率比檢出率更重要？

> 一個典型的個人開發者工作流：
> 1. 看到插件報告「⚠️ 檢測到可疑 Shell 命令」
> 2. 看了一眼，是個誤報（是測試代碼）
> 3. **卸載插件**
> 4. 永遠不會再裝
>
> 對個人開發者來說，**信任成本**比企業用戶更高——他們沒有安全團隊幫忙分辨真假，只能靠自己。
>
> 一個誤報 = 失去一個用戶。**我們寧可漏報，也不可錯殺。**

### 3. 為什麼 MCP 要重命名？

> 用戶心智模型：
> - 「Skill」 = 我安裝的東西，做一件事
> - 「MCP」 = 一個配置項，比較技術向
>
> 如果我們在報告里寫「MCP 工具風險分類」——用戶會想「我又不懂 MCP」。
>
> 如果寫「這個 Skill 依賴了一個文件讀寫工具，建議進一步審查」——用戶立刻明白「哦，這個 skill 不安全是因為它依賴了危險東西」。
>
> **第二種敘事更好，因為它告訴用戶「為什麼危險」，而不是「什麼技術術語」。**

### 4. 為什麼定價 $4.99 而不是 $9.99？

> $9.99/月 = $120/年。對一個個人開發者來說，這是「隨時可棄」的價格。
>
> $4.99/月 = $60/年。這是用戶「猶豫一下會訂」但「猶豫太久會忘」的價格——心理學上的「衝動訂閱甜蜜點」。
>
> 對**個人開發者**來說，月費 vs 年費的選擇是：活躍用戶選年費（$39），偶爾用戶選月費（$4.99）。兩個價位覆蓋兩類用戶。

### 5. 為什麼不做企業功能？

> 即使有企業客戶主動來詢單：
> - 個人開發者產品**很難撐起企業銷售**（無 BD、無售前、無合同流程）
> - 企業客戶要求 SLA、安全審計、定制開發，會**拖垮核心產品迭代**
> - NVIDIA SkillSpector 等大廠在企業市場已有先發優勢，**正面競爭必輸**
>
> **唯一正確的應對**：禮貌拒絕，引導到開源版本，引薦給其他企業安全廠商。把時間留給個人開發者市場。
